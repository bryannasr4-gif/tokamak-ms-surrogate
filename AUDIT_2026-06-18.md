## 4. FINDINGS & CORRECTIONS

### 4.1 (Corrected) Phase-1 closed-loop — a claim was retracted
The original closed-loop reported "+89%, gradient beats baselines." That run measured the *start* in a different
numerical config (`OMP=1` grid value 0.215) than the *destinations* (`OMP=4`). Re-run cleanly at `OMP=1` with the
start re-solved in-config:
- start m_s **0.306** → gradient ascent **0.431 (+0.125, +41%)** > analytic-κ 0.424 (+0.118) > fd 0.414 (+0.108).
- **Robust:** the gradient is accurate (cosine 0.956, sign 100%) and reliably raises true m_s by ~3× the noise floor.
- **Retracted:** "gradient beats the analytic-κ heuristic" — the margin (~0.007) is *within* the ~0.04 noise floor.
  In 2-D, elongation dominates, so a κ-heuristic is competitive. **The advantage is deferred to higher-D Phase 2.**

### 4.2 (New) Numerical reproducibility floor ≈ 10% — the ill-conditioned inverse solve
Same canonical shape, m_s = 0.420 / 0.424 / 0.384 / 0.417 at `OMP=1/2/4/8` (≈10% spread); bit-identical within a
fixed config. The coil **inverse** solve is ill-conditioned (the SBI-era §4.2 lesson) and amplifies FP
summation-order differences. **Required:** fix one BLAS config + one machine build for all labels; quantify and
report this floor; in Phase 2, reduce it (tighter tolerance, or **forward** sampling of currents/profiles, which
is well-conditioned, instead of inverse-solving to target shapes).

### 4.3 (New) Machine-build non-determinism *within a process* — avoided by Phase-1 design
`refine_passive.py:26` uses a module-level `LatinHypercube(seed=42)` whose state advances per call, so building
the machine **twice in one process** diverges ~20% (this caused a misleading early reading). Each Phase-1 worker
builds **once** per process, so the grid is unaffected — *verified* by two processes reproducing m_s to 10 digits.
**Required for Phase 2:** build the machine once and reuse/serialize it (or reset the engine seed per build);
never build multiple machines in one process without reseeding.

## 7. Phase-0 addendum (2026-06-19) — what Phase 0 confirmed and corrected
Full detail in `PHASE0_PROTOCOL.md`. Net: the foundation stands; three refinements/corrections.

- **(Confirmed) m_s label trust.** Independent recomputation of the Portone margin three
  algebraically-distinct ways matches FreeGSNKE to **0.000 %** (bar was <5 %). Exactly one positive
  eigenvalue = the single n=0 vertical mode. GATE criterion met decisively.
- **(Resolved) the m_s convention + a FreeGSNKE code-comment correction.** Verified (high
  confidence, multi-source: Portone NF 45 (2005) 926; Humphreys NF 49 (2009) 115003 eq. 4; FUSE
  arXiv:2409.05894; Olofsson OSTI-1960105): **m_s > 0 = stable, m_s = 0 = ideal-MHD marginal,
  bigger m_s = more stable**, m_s→0 = controllability boundary. FreeGSNKE's inline comment
  `# the positive (i.e. unstable) eigenvalues` in `calculate_stability_margin` is a **copy-paste
  mislabel** from the growth-rate routine — the *code is correct*, the comment is wrong. **Do not
  quote that comment in the paper.** Also: GSPulse/Pertnet use γ, not m_s by name (sharpens novelty).
- **(Refined) the noise floor.** The audit's "~10 %" was **cross-BLAS-thread** spread; the
  10-shape study gives m_s **median 4.9 %, max 11.4 %** (γ median 4.7 %, max 19 %), **worst near the
  marginal boundary**. Crucially, **within a fixed config m_s is bit-reproducible (12 digits,
  cross-process)** — so locking OMP=1 removes this floor entirely. Newly characterized **systematic**
  protocol-dependence of the *absolute* m_s: **retained-mode count is dominant** (`fix_n_vessel_modes=20`
  is unusable; 40→80 shifts m_s **+~10 %** → m_s is *not* mode-converged at 40), grid ≤7 %, and inverse
  tol ≤10 % beyond 1e-6 (but 1e-6 is corroborated by the 129×129 high-res value; tighter tol chases
  the ill-conditioned inverse). These are systematic biases, not random noise → forward sampling
  (Phase 1.5) is the root-cause fix.
- **(Corrected) environment fact.** Installed **scipy is 1.15.3**, not 1.11.4 (RESULTS.md A1 figure
  was wrong; corrected in `PHASE0_PROTOCOL.md` and RESULTS.md A1).
- **(New) protocol lockdown + serialized machine.** Locked protocol defined (OMP=1; one serialized
  tokamak; isolated cold solves; 65×65; 40 modes; tol 1e-6). Machine pickled once

  m_s = 0.419940486916 bit-for-bit.
